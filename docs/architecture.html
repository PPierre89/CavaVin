CavaVin · Vue d'ensemble

Une image du système

Un conteneur unique posé sur le NAS : Django sert l'API et le bundle de la SPA, un seul fichier SQLite porte à la fois le catalogue mutualisé et les caves privées. L'identification d'un vin interroge toutes les sources activées en parallèle, puis arbitre leurs réponses.

Déploiement

Un seul conteneur

  • Django sert l'API et le bundle de la SPA via WhiteNoise — pas de reverse proxy à côté.
  • Gunicorn, timeout 120 s : les appels vision doivent tenir sous ce plafond.
  • Image publiée sur GHCR, tirée par docker compose sur le NAS.
  • Sauvegarde = copier le dossier data/ (base + photos d'étiquettes).

Confidentialité

Un fichier, deux étages

  • catalog — domaines, cuvées, cépages : lisible par tous, alimenté par la communauté.
  • cellars + inventory — caves, bouteilles, dégustations : filtrés par request.user, .none() pour l'anonyme.
  • L'export du catalogue portable purge tout le reste — aucune donnée privée ne circule.

Identification

Toutes les sources

  • Photo ou nom : la cascade interroge chaque source activée en parallèle.
  • Chaque réponse devient une observation par canal ; la consolidation arbitre champ par champ.
  • Le repli OCR + LWIN tourne dans le conteneur : utilisable sans aucune clé d'API.
